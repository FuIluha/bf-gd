# LDPC Decision Energy Explorer

Локальное веб-приложение для пошагового исследования FTGDBF, PMGDBF и GDMS
на одном фиксированном наборе кодовых слов и реализаций AWGN.

## Возможности

- слайдеры и ручной ввод всех параметров декодера;
- изменение количества слов и SNR прямо в интерфейсе с пересозданием набора;
- закреплённый сверху график распределений и отдельная прокрутка настроек;
- неизменяемые снимки состояния и линейные шаги назад/вперёд;
- категории, их названия и признаки по оси X задаются самим декодером;
- FTGDBF/PMGDBF: верные и ошибочные действия по битам; GDMS: четыре типа
  направления шага `Δq` и изменения знака сообщения по рёбрам;
- плотность вероятности или количество битов, линейная или логарифмическая
  ось Y гистограммы; BER/FER всегда показаны в логарифмической шкале;
- адаптивные общие бины по правилу Freedman–Diaconis с безопасными fallback;
- текущие и предварительные BER/FER;
- сохранение/загрузка всей сессии, экспорт CSV/JSON/PNG и наложение истории
  из второй сессии;
- воспроизводимая случайная маска PMGDBF, не зависящая от числа потоков.

## Запуск

Из корня репозитория:

```bash
source .venv/bin/activate
pip install -r visualisation/error_by_energy_visualisation/requirements.txt
python -m visualisation.error_by_energy_visualisation
```

По умолчанию заранее создаются 1000 всенулевых кодовых слов при SNR = 1 dB,
используется seed 1 и один рабочий поток. При BPSK переданным символом для
каждого бита является `+1`. Эти значения можно изменить в разделе «Набор
кадров» и нажать «Применить набор». Это пересоздаёт входные слова и шум с тем
же seed, очищает историю шагов и сравнение. Пока набор не применён, все шаги
и декодеры сравниваются на одних данных. Начальные значения задаются при запуске:

```bash
python -m visualisation.error_by_energy_visualisation \
  --frames 1000 \
  --snr 1.0 \
  --seed 1 \
  --workers 8 \
  --port 8050
```

Другой JSON кода можно явно выбрать через `--code`. Если он содержит поле
`generator`, приложение будет генерировать случайные информационные слова;
для этого должна быть собрана библиотека `lbc_encoder_impl.so`.

После запуска открыть `http://127.0.0.1:8050`.

Для сервера приложение можно слушать на всех интерфейсах:

```bash
python -m visualisation.error_by_energy_visualisation \
  --host 0.0.0.0 \
  --port 8050 \
  --workers 32 \
  --frames 1000
```

Порт должен быть разрешён правилами сервера. Более безопасный вариант —
оставить `--host 127.0.0.1` и открыть SSH-туннель с локального компьютера:

```bash
ssh -L 8050:127.0.0.1:8050 entropy
```

Число `--workers` управляет потоками кодирования и одного шага декодера.
Веб-сервер также обслуживает HTTP-запросы в потоковом режиме. Большие
значения следует подбирать по числу доступных CPU и памяти узла.

## Семантика шага

На снимке `k` график является предпросмотром решения `k → k+1` с текущими
значениями контролов. Кнопка «Вперёд» фиксирует новый снимок. «Назад» только
перемещает указатель, не меняя уже рассчитанные состояния. Новый шаг из
прошлого удаляет прежние последующие снимки и продолжает единственную
линейную историю.

Для PMGDBF случайные числа детерминированы seed и номером итерации. Поэтому
изменение `alpha`, `delta`, `p`, `rho` или `L` на одном снимке не подменяет
эффект параметров новой случайной реализацией.

Сравнение принимается только для истории на том же самом фиксированном
батче (проверяется SHA-256 входных значений и переданных символов). Это не
даёт случайно наложить BER/FER от другого SNR или seed.

## Проверка

Короткие unit-тесты не запускают статистический эксперимент:

```bash
python -m unittest discover \
  -s visualisation/error_by_energy_visualisation/tests \
  -v
```

Сессия сохраняется как сжатый NPZ и включает входной набор и все снимки.
JSON и CSV содержат компактный текущий срез, а PNG выгружается кнопкой
камеры в панели Plotly.

## Добавление декодера

Дополните **исходный Python-декодер** вторым базовым классом
`VisualizableDecoderBase` из `base.py` (первым остаётся `BinLdpcDecoderBase`).
Отдельный численный декодер для UI создавать не нужно. Метод `describe()` возвращает
`DecoderSpec`: ключ и название декодера, параметры (`ParameterSpec`), доступные
величины по оси X (`ObservableSpec`), категории (`CategorySpec`) с названиями и
цветами. Общий интерфейс строит все контролы, переключатели и легенду из этого
описания. При необходимости переопределите `validate_parameters()` для
проверок между параметрами.

Реализуйте `initial_state()` (состояние одного слова), `step_state()` (один шаг
и диагностические массивы), `hard_decision()` (BPSK-знаки для BER/FER),
`is_decoded()` (правило остановки) и `classify()` (словарь «ключ категории →
`CategorySamples`»). Классификатор получает старое и новое состояния,
диагностику, маску активных кадров и переданные символы. Наблюдение может
входить в несколько категорий или не входить ни в одну. Метод `decode()`
исходного декодера должен использовать тот же `step_state()`, что и UI.
Визуализатор вызывает его отдельно для каждого активного слова, а классификацию
запускает на получившемся батче.

Затем добавьте **одну строку** `"полный.путь.модуля:ИмяКласса"` в
`SUPPORTED_DECODERS` файла `supported.py`. Остальные части приложения не
требуют веток по имени алгоритма. Посмотрите `ldpc_py/bin_ldpc_gdms.py` как пример
декодера с состоянием на рёбрах и четырьмя категориями.

Чекбоксы скрывают категории на гистограмме, в сводке и экспорте;
классификацию и историю они не меняют. BER/FER GDMS считаются по знакам `x`,
а распределения его шага — по сообщениям `q`. Ноль трактуется как знак `+1`.

Новый формат сессии имеет версию 2. Загрузка сессий старого формата не
поддерживается.
